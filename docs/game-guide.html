1. Как играть

Ты — рыцарь в ночной арене. Сверху открывается фиолетовый портал, из него падают враги. Между волнами открывается магазин, а в центре арены загорается зелёная зона: зашёл в неё — пришла следующая волна. Каждая 5-я волна — босс. Смерть заканчивает забег и показывает статистику.

2. Игровой цикл

Кто чем управляет

  • WaveManager — единственный владелец состояния волны: IDLE → SPAWNING → FIGHTING → LOOTING → RESHAPING → CLEARED.
  • Portal — визуал: дышит, светится, «выплёвывает» врагов по сигналу менеджера.
  • WaveGate — зелёная зона: копит заряд, пока игрок внутри, затем просит start_wave(). Загорается только после того, как арена перестроилась.
  • PlatformManager — генерирует раскладку платформ и анимирует переезд между волнами.
  • Shop — паузит дерево и продаёт апгрейды/оружие за монеты.
  • World — дирижёр: связывает системы и UI сигналами, сам ничего не считает.

4. Лут

🪙 Монета
8-кадровая анимация вращения. Выпадает из врагов (1–10 штук) и горшков. Магнитится в радиусе 42 px (апгрейд LOOT MAGNET добавляет +45).
❤️ Сердце
Восстанавливает 1 HP. Шанс с врага 5%, из горшка — 24%. Притягивается всегда (радиус минимум 30).
💎 Гем
Редкий дроп из горшка (18%): 8–14 монет одним пикапом. Звучит выше на две октавы.
🏺 Горшок
Падает с неба во время волны каждые 6–10 секунд (75% шанс), приземляется на пол или на платформу. Разбивается с одного удара, лут зависит от броска: 3–6 монет / 2 монеты + сердце / гем.
🧰 Сундук
14% небесных брейкаблов. Два удара, внутри 18 монет + гем + 70% шанс сердца. Даёт тряску камеры и звук «дзинь» — маленький праздник посреди боя.

Пикапы: два состояния движения

Пока предмет не коснулся земли — он подчиняется «баллистике» (гравитация 900, рассеивание ±90 по X при вылете). После касания — «парение»: подъём на 8 px и синусоида _bob. Как только игрок в радиусе магнита — предмет переключается в режим полёта к игроку со скоростью, зависящей от расстояния (clamp(340 − dist·0.6, 120, 420)). Такая трёхступенчатая модель даёт читаемый «вылет → приземление → притяжение» без физических тел.

6. Техника: процедурный пиксель-арт

Ни одного скачанного спрайта: вся графика (151 PNG) собирается скриптом Tools/artgen/ на Pillow. Это значит, что арт можно переделать одним запуском, он всегда воспроизводим и его удобно ревьюить в диффе.

6.1 Мини-движок рисования (px.py)

Базовые примитивы: rect, ellipse, line, circle, paste, плюс важные для пиксель-арта вещи: авто-обводка силуэта, вертикальный градиент, дизеринг, glow и альфа-смешение.

def outline(self, color, diagonals=True): # добавляет 1px контур вокруг непрозрачного силуэта additions = [] for y in range(self.h): for x in range(self.w): if self.opaque(x, y): continue for dy in (-1, 0, 1): for dx in (-1, 0, 1): if self.opaque(x + dx, y + dy): additions.append((x, y)) for (x, y) in additions: self.set(x, y, color)

Контур — главный секрет читаемости пиксель-арта на тёмном фоне: тёмная обводка отделяет спрайт от фона без свечения и блюра.

6.2 Параметрические персонажи

Все гуманоиды собираются одной функцией с параметрами позы (bob, arm, leg) и палитрой. Кадр анимации — просто набор смещений:

anims["run"] = [ _orc(pal, bob=1, arm=-1, leg=(2, -2)), # левая нога вперёд, тянемся рукой _orc(pal, bob=0, arm=0, leg=(1, -1)), _orc(pal, bob=1, arm=1, leg=(-2, 2)), _orc(pal, bob=0, arm=0, leg=(1, -1)), ]

Дальше это режется в горизонтальную ленту: sheet(frames, "Enemies/orc_run.png"). Ленты — это то, что читает Godot; никаких .aseprite и ручной нарезки.

Почему не рисовать вручную: 13 врагов × 6 анимаций × 4–6 кадров = ~400 кадров. Скрипт делает их за секунду, гарантирует единый стиль (одна палитра, один контур, один размер клетки) и позволяет поменять палитру одним replace.

7. Техника: sprite sheet → SpriteFrames в рантайме

Обычно SpriteFrames — это .tres-ресурс, который руками заполняют в редакторе. Здесь он собирается кодом: любая лента превращается в анимацию одной строкой, а описания анимаций лежат в каталоге врага.

static func add(sf: SpriteFrames, spec: Dictionary) -> void: var tex: Texture2D = load(spec["path"]) var count: int = tex.get_width() / int(spec["fw"]) # лента = 1 ряд кадров sf.add_animation(spec["name"]) sf.set_animation_speed(spec["name"], spec["fps"]) sf.set_animation_loop(spec["name"], spec["loop"]) for i in count: var at := AtlasTexture.new() # регион = кадр at.atlas = tex at.region = Rect2(i * int(spec["fw"]), 0, spec["fw"], spec["fh"]) sf.add_frame(spec["name"], at, 1.0, i)

Враг в _ready() просто просит: SheetAnim.build(EnemyCatalog.anim_specs(type_id, data)) — и получает idle/run/attack/death, причём slam, summon и charge добавляются только если файл существует.

Выравнивание по земле считается из коллизии, а не подбирается на глаз:

sprite.position.y = body.y * 0.5 - frame.y * scale * 0.5 + lift
Плюс: одна сцена Enemy.tscn обслуживает 13 врагов. Замена врага = замена словаря; новый моб не требует новой сцены.

8. Техника: bitmap-шрифт из 60 глифов

Обычный TTF в пиксельной игре выглядит инородно. Я сгенерировал собственный шрифт 5×7: глифы заданы строками, потом собираются в атлас и описываются в формате BMFont (.fnt + .png), который Godot импортирует как обычный FontFile.

"A": ".###./#...#/#...#/#####/#...#/#...#/#...#", "B": "####./#...#/#...#/####./#...#/#...#/####.", "4": "...#./..##./.#.#./#..#./#####/...#./...#.",

Каждый глиф печатается в атлас 16×N в двух масштабах (scale=2 → 10×14), а рядом пишется дескриптор:

char id=65 x=0 y=0 width=10 height=14 xoffset=0 yoffset=0 xadvance=12 page=0 chnl=15

В игре шрифт ставится один раз в тему (PixelUI.font()), а размеры — кратные базовым 14/28/42/56, чтобы глифы оставались пиксельными без размытия.

9. Техника: «уютный» процедурный звук

Все 23 звука синтезируются в WAV математикой (осцилляторы + огибающие + лёгкий шум), без сэмплов и лицензий. Вторая итерация звука делалась по субъективной жалобе «слишком тревожно» — вот какие правила убрали тревогу:

Только синус и треугольник
Квадрат и пила (главные источники «ретро-воя») полностью убраны. Именно они давали ощущение сирены на уроне и смерти.
Low-pass на каждый звук
Однополюсный фильтр 1.4–6 кГц убирает жёсткие верхние гармоники. Это самый быстрый способ «согреть» синтез.
Мажорные интервалы
Кнопки — C-E-G-C, лечение — до-мажорное арпеджио, смерть — мягкая колыбельная C-A-F-C вместо минорного стинга.
Мягкая атака и пик 0.6
Атака 5–15 мс (щелчки исчезают), нормализация в 0.6, tanh-лимитер и мастер −8 дБ: даже 30 одновременных попаданий не режут слух.
Шум — только транзиент
Шум больше не «тело» звука, а короткий воздушный призвук: свист взмаха, пыль взрыва, «шух» карт.
Короткие и тихие
Хит — 0.1 с деревянный «ток», монета — две ноты маримбы, крит — колокольчик. Чем короче звук, тем меньше усталости в 40-минутном забеге.
def marimba(t, freq, decay=9.0): """Синус + тихая октава с экспоненциальным телом — тёпло и «деревянно».""" env = math.exp(-t * decay) return (sine(t, freq) + 0.28 * sine(t, freq * 2.0) * math.exp(-t * decay * 1.8)) * env def finish(samples, cutoff=3000.0, peak=0.6): return smooth_edges(lowpass(normalize(samples, peak), cutoff)) # гитарный пример: монета — «чинг» из двух нот маримбы (G5 → D6) def sfx_coin(dur=0.24): def fn(t, p): f = G5 if p < 0.42 else 1174.66 return marimba(t, f, 9.0) * 0.75 + sine(t, f * 2.0) * math.exp(-t * 18.0) * 0.1 return finish(render(dur, fn), cutoff=5200.0, peak=0.5)
Вывод: «тревожность» звука — это почти всегда квадратная волна + минор + отсутствие фильтра. Три правки (форма волны, интервал, low-pass) меняют настроение сильнее, чем любая громкость.

10. Техника: camera shake (trauma + Perlin-шум)

Классический вопрос: «как сделать тряску, чтобы не тошнило и при этом чувствовалось». Ответ — модель trauma из доклада ГеймМеханик / Squirrel Eiserloh:

  • события не двигают камеру напрямую, а добавляют травму от 0 до 1;
  • к камере применяется квадрат травмы — мелкие события почти не заметны, крупные бьют сильно;
  • смещение берётся из гладкого шума (FastNoiseLite), а не из randf() — иначе получается дрожание, похожее на баг рендера;
  • травма линейно затухает — камера всегда возвращается в ноль.
func add_trauma(amount: float, direction := Vector2.ZERO) -> void: trauma = clampf(trauma + amount, 0.0, 1.0) if direction.length() > 0.01: _shake_dir = direction.normalized() # направленный «пинок» func _physics_process(delta): _t += delta trauma = maxf(0.0, trauma - trauma_decay * delta) # затухание 1.6/сек var shake := trauma * trauma # ← ключ: квадрат if shake > 0.0001: var nx := _noise_x.get_noise_2d(_t * 100.0, 0.0) # два разных seed var ny := _noise_y.get_noise_2d(0.0, _t * 100.0) offset = Vector2(nx, ny) * max_offset * shake rotation = _noise_roll.get_noise_2d(_t * 100.0, 100.0) * max_roll * shake

Три шумовых поля (X, Y и наклон) с разными seed — так смещения не коррелируют и картинка «дрожит» естественно. Параметры: max_offset = (14, 10) px, max_roll = 0.035 рад, частота 22.

Zoom punch

Отдельный сигнал FX.zoom_punch(0.18) кратко «отъезжает» зумом (до −12% за кадр, возврат 1.6/сек). В связке с shake крупные события читаются как ударная волна через объектив.

Антитошнотные предохранители: базовая камера плавно следует за игроком с look-ahead по скорости (до 48 px), травма ограничена 1.0, наклон максимум 2°, а лимиты Godot не дают камере выйти за арену. Плюс отдельный set_look_offset() поднимает взгляд на портал во время спавна (см. главу 17.4).

11. Техника: хит-стоп, slow-mo и вспышки

Хит-стоп — это заморозка всего мира на несколько кадров в момент удара. В Godot это делается через Engine.time_scale, но есть подвох: если восстанавливать time_scale обычным таймером, он сам замедлится. Поэтому таймер создаётся с флагом ignore_time_scale.

func hitstop(duration: float) -> void: var token := _hitstop_owner Engine.time_scale = 0.05 # create_timer(sec, process_always, process_in_physics, ignore_time_scale) await get_tree().create_timer(duration, true, false, true).timeout if token == _hitstop_owner: # не отменяем более поздний hitstop Engine.time_scale = 1.0

Длительности: обычный удар 0.035s, крит 0.05s, урон игроку 0.09s. Больше — уже не «сочность», а тормоза.

Slow-mo для смерти — тот же приём, но с 0.3× на 1.2s реального времени, и только после него запускается экран статистики. Вспышка экрана — CanvasLayer с ColorRect, альфа которого гасится твином за 0.28s:

func flash(color := Color.WHITE, strength := 0.35) -> void: _flash_rect.color = Color(color.r, color.g, color.b, strength) create_tween().tween_property(_flash_rect, "color:a", 0.0, 0.28)

12. Техника: всплывающие числа урона

Каждое число — отдельный Node2D с Label и своей физикой: начальная скорость (−62 px/s по Y, ±16 по X), гравитация 120 px/s², затухание альфы в последние 45% жизни.

func _process(delta): _life += delta global_position += _velocity * delta _velocity.y += 120.0 * delta _velocity.x = lerpf(_velocity.x, 0.0, 3.0 * delta) modulate.a = clampf(1.0 - (_life - LIFE * 0.45) / (LIFE * 0.55), 0, 1)

Крит отличается цветом (золотой), размером (14 вместо 10) и «пружинкой» масштаба через Tween с chain(). Числа — самый дешёвый способ объяснить игроку, что апгрейд на +15% урона работает.

13. Техника: генерация волн по бюджету

Волна не хардкодится: у каждого врага есть вес (стоимость спавна), у волны — бюджет очков. Алгоритм набирает врагов, пока бюджет не кончится, и с каждым взвешенным выбором предпочитает дешёвых (вес обратный).

static func build_wave(wave: int, rng: RandomNumberGenerator) -> Array: var ids := spawnable_ids(wave) # только те, чей min_wave пройден var budget := 4.0 + wave * 1.55 # волна 1 → 5.5, волна 10 → 19.5 if wave % 5 == 0: budget *= 0.55 # в босс-волне меньше миньонов var out := [] while budget > 0.5: var pick := _weighted(ids, rng, budget) # slime(3.0) … golem(1.0) budget -= float(get_type(pick)["weight"]) out.append(pick) return out

Дополнительно: шанс «элиты» (×1.9 HP, +2 монеты, полоска здоровья) растёт от 3% на 5-й волне до 22% на 19+; спавн идёт с интервалом 0.42s из портала с разбросом ±46 px, поэтому враги не слипаются в одну точку.

Как считается конец волны

Менеджер не полагается на счётчик: он спрашивает get_tree().get_nodes_in_group("enemy").size(). Призванные боссом миньоны и размножившиеся слизни попадают в эту же группу, поэтому волна не закончится, пока жив хоть кто-то. Плюс «сеть безопасности» в _clamp_bounds() возвращает в арену моба, которого физика вытолкнула за стену — иначе волна могла бы зависнуть навсегда.

14. Техника: ИИ врагов через архетипы

Вместо state-machine и отдельных классов — одна функция _ai(), которая смотрит на строку archetype и раздаёт поведение. Это даёт 13 разных врагов при нулевом дублировании кода и без риска «застрять в состоянии».

func _ai(delta): var to_target := _to_target() var dist := to_target.length() # общий предохранитель: не стоять на платформе, если игрок внизу if not flying and is_on_floor() and to_target.y > 42.0 and _is_on_platform(): _drop_timer = 0.25; set_collision_mask_value(2, false) match archetype: "walker": _walk_towards(to_target); _melee_if_close(dist) "flyer": _fly_towards(to_target, delta) # игнорирует гравитацию "thrower": _kiter(...); try_shoot(dist, 220.0) # держит дистанцию "leaper": _leaper(to_target, dist) # прыжок + паутина "charger": _charger(to_target, dist) # разгон на 110–420 px "slammer": _walk_towards(to_target); _do_slam() # телеграф → шоквейв ...

Почему отказ от булевого «attacking»

В первой версии был флаг attacking: bool, из-за которого босс мог навсегда замереть в анимации удара (флаг ставился, а снять его было некому). Заменил на таймер блокировки:

func _lock_action(seconds: float) -> void: action_lock = maxf(action_lock, seconds) # ИИ стоит ровно столько времени attacking = true # в _physics_process: if action_lock > 0.0: action_lock -= delta if action_lock <= 0.0: attacking = false velocity.x = move_toward(velocity.x, 0.0, 1600.0 * delta) else: _ai(delta)

Таймер не может «залипнуть»: даже если атаку прервали смертью, уроном или прыжком, через N секунд моб снова живой и агрессивный. Это общий урок: в игровом коде предпочитайте таймеры булевым флагам.

Спец-механики

  • Телеграф перед слэмом: сначала FX telegraph (красное кольцо, 0.6s), потом AreaDamage.explode() — игрок успевает уйти.
  • Шоквейв по приземлению: флаг _slam_pending ставится при прыжке, «взводится» только когда моб реально в воздухе и срабатывает при касании земли.
  • Летуны: цикл «караулить → вспышка → пикировать» и тень на земле — подробно в главе 16.4.
  • Замедление и стан: apply_slow() и apply_stun() пишут множители в slow_factor/stun_timer, а _update_modulate() красит спрайт в синий/жёлтый — статус всегда виден.

15. Техника: оружие — круг + угол, проджектайлы

Ближний бой не использует Area2D: в момент кадра попадания делается shape query круга, а затем проверяется угол. Это точно, дёшево и не оставляет «висящих» включённых хитбоксов.

var circle := CircleShape2D.new() circle.radius = reach # дальность оружия × бонусы var params := PhysicsShapeQueryParameters2D.new() params.shape = circle params.transform = Transform2D(0.0, global_position) params.collision_mask = ENEMY_LAYER | BREAKABLE_LAYER var results := space.intersect_shape(params, 24) for r in results: var to_body: Vector2 = body.global_position - global_position # дуга: половина угла оружия (у молота 70°, у копья 20°) if absf(angle_difference(to_body.angle(), aim.angle())) > arc * 0.5: continue body.take_damage(dmg, to_body.normalized() * kb, crit)

Дальнее — Projectile с флагами: pierce (сколько целей пробивает), homing_strength (сферы посоха подруливают), slow_amount (паутина), плюс учёт крита и лайфстила, которые передаются в снаряд до выстрела.

Мультивыстрел и разброс

var count := 1 + int(GameState.get_stat("projectile_bonus")) for i in count: var offset := (float(i) - (count - 1) * 0.5) * 0.09 # веер в радианах spawn_projectile(..., Vector2.from_angle(aim.angle() + offset), ...)

Тяжёлое оружие добавляет stun цели, лайфстил лечит целыми единицами (накопитель lifesteal_pool), а крит даёт hitstop — поэтому разные оружия ощущаются по-разному, хотя код один.

16. Техника: магазин и математика апгрейдов

Все апгрейды — чистые данные: словарь эффектов, который складывается в статы забега. Никакой логики «если апгрейд X, то...» — только сложение чисел.

{"id": "damage", "name": "SHARP BLADES", "desc": "+15% DAMAGE", "cost": 14, "max": 6, "rarity": 0, "effects": {"damage_mult": 0.15}}

Применение — просто прибавка к словарю статов, а цена растёт от волны и уровня:

func upgrade_cost(u: Dictionary) -> int: return int(round(u.cost * (1.0 + 0.06 * (wave - 1)) * (1.0 + 0.35 * upgrade_level(u.id))))

Генерация предложения: перетасовать пул, взять первые валидные (не исчерпавшие max), с шансом 45% подсунуть оружие. Реролл дорожает на 3 монеты за использование внутри одного магазина.

Анимации UI (то, что делает магазин «живым»)

  • карты влетают со стаггером 0.08s: scale 0.85 → 1.0 c TRANS_BACK и fade 0.22s;
  • ховер карты — твин scale → 1.05 за 0.12s;
  • заголовок «WAVE N CLEARED» — overshoot масштаба;
  • кнопки неактивны, когда монет не хватает (серый цвет = понятная обратная связь);
  • покупка: жёлтая вспышка экрана, звук buy, карта становится SOLD.

Мелочь, которая ломала EQUIP

Повторное «EQUIP 0» (оружие уже куплено — можно взять бесплатно) не срабатывало: GameState.spend(0) возвращает false, а магазин трактовал это как «не хватило монет». Плюс кнопка при нехватке денег уходила в disabled и молчала вместо объяснения. Теперь нулевая цена обрабатывается явно, кнопки никогда не блокируются, а клик по недоступной карте трясёт её и показывает «NOT ENOUGH COINS».

Экономика: обычный враг даёт 1–6 монет (со множителем GREED до +100%), бонус за волну 6 + wave×2, горшок 3–6 монет или 8–14 гемом. Первый магазин на 1-й волне обычно открывает 1–2 покупки — темп задан так, чтобы к 5-й волне у игрока было 2–4 апгрейда или новое оружие.

16. Техника: читаемость (радиус оружия, полёт, ориентация)

Три правки после плейтеста — все про то, что игрок должен понимать без объяснений: куда он бьёт, где летает враг и с какой стороны находится оружие.

16.1 Индикатор радиуса оружия

Под ногами рисуется полупрозрачный сектор, точно совпадающий с хитбоксом: радиус = range × (1 + бонус дальности), угол = arc оружия. Для дальнего боя — пунктирный луч и кружок на пределе дистанции. Рисуется вручную через _draw() и пересчитывается каждый кадр, поэтому апгрейды видно мгновенно.

func _draw_melee(aim: Vector2, range_stat: float) -> void: var reach := float(player.weapon["range"]) * range_stat var arc := deg_to_rad(float(player.weapon["arc"])) var base := aim.angle() # залитый сектор = реальная зона попадания draw_colored_polygon(points, Color(0.55, 0.95, 1.0, 0.10)) draw_arc(Vector2.ZERO, reach, base - arc * 0.5, base + arc * 0.5, 26, Color(0.55, 0.95, 1.0, 0.42), 1.8, true)
Почему это важно: до индикатора игрок не понимал, достаёт ли он до врага — 40 пикселей радиуса при зуме 2 субъективно читаются совсем иначе, чем в цифрах. Теперь «достаю / не достаю» решается за один взгляд.

16.2 Ориентация оружия: один флип, а не два

Меч «не разворачивался», потому что зеркалирование применялось дважды: у родителя Weapon.scale.x = facing и у самого спрайта flip_h = facing < 0. Два зеркала взаимно уничтожаются — визуально оружие всегда оставалось справа (а анимация замаха — с прежней стороны).

# правильно: зеркалим один раз — весь узел Weapon, включая пивот weapon_root.scale.x = float(facing) weapon_sprite.flip_h = false weapon_sprite.position = HAND_OFFSET - WEAPON_PIVOT

Пивот ствола оружия равен точке хвата в кадре (20,34), поэтому position = HAND_OFFSET - PIVOT ставит рукоять ровно в руку рыцаря. Тот же приём убрал двойной флип у VFX замаха: дуга слаша уже симметрична относительно направления, ей хватает одного rotation = aim.angle().

16.3 Тень летающих врагов

Летучая мышь летала без гравитации — и было непонятно, где она вообще находится по высоте. Теперь под ней на пол/платформу проецируется эллипс: луч вниз находит поверхность, а альфа и размер зависят от высоты (до 420 px).

var hit := space.intersect_ray(params) if hit.is_empty(): visible = false; return _height = clampf(hit.position.y - from.y, 0.0, MAX_HEIGHT) global_position = Vector2(enemy.global_position.x, hit.position.y - 1.0) var t := 1.0 - _height / MAX_HEIGHT scale = Vector2(0.45 + 0.75 * t, (0.45 + 0.75 * t) * 0.38) modulate.a = 0.10 + 0.30 * t

16.4 Понятный полёт мыши: караулить → вспышка → пикировать

Раньше мышь просто «висела и подъедала» — поведение не читалось. Теперь это цикл из трёх фаз с телеграфом:

1. HOVER — держит дистанцию сверху-сбоку (42 px в сторону, +26 вверх)
→
2. WINDUP 0.34s — замирает и подсвечивается тёплым
→
3. DIVE 0.36s — бросок 470 px/s сквозь игрока
→
4. RECOVER + кулдаун 2.1s
if _windup_timer > 0.0: _windup_timer -= delta velocity = velocity.lerp(Vector2.ZERO, 8.0 * delta) # замирает _telegraph = 1.0 # и светится: игрок видит «сейчас прыгнет» if _windup_timer <= 0.0: _dive_dir = (target.global_position - global_position).normalized() _dive_timer = 0.36

Телеграф реализован одним полем _telegraph, которое подмешивается в общий проход _update_modulate() — тот же, что отвечает за вспышку урона, замедление и стан. Одна точка правды для «как спрайт выглядит сейчас».

17. Техника: процедурные арены (платформы + портал)

Арена не статичная декорация: каждую чётную волну и после каждого босса она перестраивается. Платформы меняют количество и позиции, а портал открывается на противоположной стороне от центра — так каждый раунд начинается в новом месте.

17.1 Раскладка платформ

PlatformManager держит список «слотов» по X и «этажей» по Y и набирает из них 3–6 плит. Правила простые, но дают играбельный результат:

const SLOTS := [-490.0, -320.0, -160.0, 0.0, 160.0, 320.0, 490.0] const LEVELS := [45.0, -25.0, -95.0] # все достижимы прыжком (108 px) # правила генерации: # * не больше одной плиты в один слот на один этаж; # * нельзя ставить плиты в соседние этажи одного слота (чтобы не было «бутерброда»); # * центральный слот не используется на нижнем этаже — там зелёная зона; # * ширина плиты 1 или 2 юнита (96 / 192 px).

17.2 Анимация переезда

Переход — это три разных анимации, которые идут одновременно:

СитуацияАнимацияРеализация
Плита осталась в раскладкеедет по X/Y + тянется по ширинеTween параллельно, TRANS_SINE 0.6s, пыль на старте и финише
Появилась новаяпадает сверху и «шлёпается»старт на y−420, TRANS_CUBIC / EASE_IN 0.65s, пыль + тряска камеры при касании
Плита убранаулетает вверх и растворяетсяposition:y −380 + modulate:a → 0, затем queue_free()
Почему волну нельзя начать во время переезда: зелёная зона в этот момент выключена (RESHAPING), а игрок видит подсказку «THE ARENA IS SHIFTING…». Иначе можно было бы оказаться в воздухе без платформы под ногами. На нечётных волнах арена не двигается — пауза получается короче, и темп не провисает.

17.3 Переезд портала

Менеджер запоминает, с какой стороны был портал, и каждый раз открывает его с противоположной, на случайном расстоянии 170–430 px от центра. Визуально это телепорт: затухание → сдвиг по X → появление со вспышкой.

func _move_portal() -> void: var side := -1.0 if _portal_x >= 0.0 else 1.0 # всегда в другую сторону _portal_x = side * rng.randf_range(170.0, 430.0) _portal.call("relocate_to", _portal_x)

17.4 Кадрирование камеры под дроп

Портал висит высоко над ареной — при зуме 2 он не влезает в кадр целиком. Поэтому камера не «уезжает вверх», а подтягивается в сторону портала: вектор до цели умножается на 0.42 и обрезается по focus_max = (96, 110). Смещение маленькое (это подсказка, а не катсцена), но игрок сразу видит, откуда сыплются враги. Плюс сам кадр слегка поднимается: look_offset_y уходит с −50 к −90 и возвращается с началом боя.

if wave_manager.state == WaveManager.State.SPAWNING: camera.set_look_offset(-90.0) # чуть выше обычного camera.set_focus_point(portal.global_position) # и наклониться к порталу else: camera.set_look_offset(-50.0) camera.clear_focus()
func _update_focus(delta, player_pos): var to_point := _focus_point - player_pos _focus_goal = (to_point * focus_ratio).clamp(-focus_max, focus_max) # маленький сдвиг _focus_offset = _focus_offset.lerp(_focus_goal, focus_speed * delta)

Это дешёвый приём «постановочной камеры»: без него игроки не понимают, откуда падают враги, а с ним момент спавна превращается в маленькое шоу.

18. Техника: зелёная зона и лут-окно

Зона — Area2D с анимированным спрайтом (6 кадров, пульсирующая колонна света и стрелка). Заряд считается не по сигналам входа/выхода, а по факту пересечения каждый кадр — это устойчивее к телепортам, паузам и появлению игрока прямо в зоне:

Лут-окно (7 секунд после зачистки)

Раньше магазин открывался мгновенно и паузил игру — монеты, которые только что выпали из врагов, оставались лежать. Теперь после зачистки волны начинается фаза LOOTING: HUD показывает «COLLECT THE LOOT 7s», зона ещё не горит, и у игрока есть время обежать арену. Когда окно закрывается, Pickup.vacuum_all() подбирает всё оставшееся автоматически — ни одна монета не теряется.

func _update_looting(delta): loot_timer -= delta hint_changed.emit("COLLECT THE LOOT %ds" % maxi(0, int(ceil(loot_timer))), true) if loot_timer <= 0.0: _begin_reshape() # vacuum → платформы → портал → магазин
if _player_inside(): # get_overlapping_bodies() _charge = minf(1.0, _charge + delta / CHARGE_TIME) # CHARGE_TIME = 0.9s if fmod(_t, 0.12) < delta: FX.play("dust", global_position + ..., {"modulate": Color("#7fe6cf")}) else: _charge = 0.0 # вышел — заряд сброшен if _charge >= 1.0: entered.emit()

Этот же сигнал показывает баннер волны: слоистый CanvasLayer (25) поверх HUD, твин с TRANS_BACK на масштаб + задержка 1.5–2.1s + fade, и очередь, если события накладываются.

Зачем зона, а не таймер: игрок сам решает, когда готов — можно подобрать лут, докупить апгрейд и только потом шагнуть в свет. Это превращает «паузу между волнами» в фазу принятия решений, а не в ожидание.

19. Техника: горшки и сундуки с неба

Горшок — CharacterBody2D на своём слое физики (64). Он падает по обычной гравитации, крутится в полёте, а при касании земли «защёлкивается»: обнуляет скорость, сбрасывает вращение, пылит и щёлкает звуком. Маска коллизий 1 | 2 — значит, горшок может приземлиться и на пол, и на платформу.

Грабли: если оставить коллизию горшка по центру спрайта, он «проваливается» в пол на половину высоты, а на платформе (слой 2) вообще не задержится. Правильно — сделать точку отсчёта ногой:
_shape.position = Vector2(0, -circle.radius + 1.0) # круг стоит НА земле, а не в ней _sprite.position = Vector2(0, -frame_h * 0.5 + 1.0) # спрайт сидит на коллизии

Из тех же «небесных» брейкаблов выпадают и сундуки (14% от всех падений): им нужно два удара, внутри — 18 монет, гем и часто сердце. Сундук использует тот же скрипт, отличается только kind и таблицей лута.

Ломается по удару оружием/снарядом — break_open():

func break_open() -> void: Audio.play("pot", 0.1, -2.0) FX.play("explosion", global_position, {"scale": 0.45, "modulate": Color(1.0, 0.85, 0.6)}) FX.shake(0.12) var roll := randf() if roll < 0.58: Pickup.scatter(holder, global_position, "coin", randi_range(3, 6)) elif roll < 0.82: Pickup.scatter(.."coin", 2); Pickup.scatter(.."heart", 1) else: Pickup.spawn(holder, global_position, "gem", randi_range(8, 14)) queue_free()

Ритм задаёт WaveManager: таймер 6–10s, шанс 75%, случайная точка по X в пределах ±520, стартовая скорость 120–220 px/s. Горшки не спавнятся между волнами — только в бою, чтобы награда приходила «по ходу дела».

20. Техника: демо-бот и headless-тесты

Проверять игру с волнами и 13 видами ИИ вручную — долго. Поэтому в проект встроен бот, который нажимает те же Input-экшены, что и человек: он реально ходит, прыгает, бьёт и заходит в зелёную зону.

# прицел — в ближайшего врага var aim := (target.global_position - player.global_position).normalized() player.aim_override = aim # в headless нет мыши # движение и действия — через настоящие экшены Input.action_press("key_right") ; Input.action_press("attack") ; _tap("dash")

22. Как перегенерировать арт и звук

# 1. вся графика + шрифт + 23 звука (нужен Python 3 + Pillow) python Tools/artgen/main.py # → Aseprites/Generated/ (151 png + manifest.json) и Aseprites/Sound/ # 2. импорт ресурсов в Godot (обязательно после генерации!) godot --headless --import --path . # 3. проверка, что ничего не сломалось godot --headless --path . --quit-after 1200 -- --autotest
Важно: если поменять PNG и не выполнить импорт, игра будет рисовать старую версию текстуры из .godot/imported/. Всегда запускайте --headless --import после генерации арта.

23. Что дальше

Мета-прогресс
Гемы за забег → постоянные бонусы между забегами. GameState уже умеет хранить статистику, нужен только слой сохранения (user://save.cfg).
Больше оружия и статусов
Лёд (замедление уже есть — apply_slow), огонь (тик урона), цепная молния (прыжок между врагами).
Альтернативные арены
Сцена арены параметризована лимитами камеры и позициями платформ — новый биом это новый набор тайлов и модификаторов волн.
Модификаторы волн
Поле wave_modifiers и вывод в баннере уже есть: «туман», «быстрые враги», «двойные монеты».
Геймпад
Ввод идёт через экшены, достаточно добавить оси и второй стик в настройки ввода.
Музыка
Генератор sfx.py легко расширить до 8-битного трекера с басовой линией на 4 такта.
